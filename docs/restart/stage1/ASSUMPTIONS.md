# Stage 1 assumptions and decisions

Updated: 2026-10-18

| ID | Assumption / decision | Rationale | Validation / limit |
| --- | --- | --- | --- |
| A1 | The pilot uses the four requested app IDs: CS2 730, Dota 2 570, HELLDIVERS 2 553850, No Man's Sky 275850. | These are explicit user-selected seeds, so Steam catalog discovery is not needed to begin. | News responses must echo the requested app ID. Names and IDs are recorded as curated seeds, not a complete catalog result. |
| A2 | Public review collection uses `IUserReviewsService/GetAppReviews` with `filter=1` (Recent), `review_type=0`, `purchase_type=1`, `languages=["all"]`, and both date bounds. | Recent is documented for exhausting pages; all languages and purchase sources reduce avoidable selection bias. | Steam may still filter/remove reviews and only returns the current revision of a review. |
| A3 | Public news collection uses `ISteamNews/GetNewsForApp` with `maxlength=0`; pages advance by `enddate` because no cursor is documented. | `maxlength=0` requests full post content. Each subsequent request uses one second before the oldest returned timestamp. Completed backfills poll the newest page on rerun and stop at the previous newest timestamp. | Equal timestamps, backdated posts, post edits, or API ordering changes can make page boundaries imperfect; GID deduplication and no-progress detection expose this. |
| A4 | Feed identity is retained independently from patch classification. | A Steam-hosted news list contains promotions, events, and other feeds; a news item is not automatically a patch. | `steam_community_announcements` is treated as Steam's publisher announcement feed; other feed names are retained as unverified/other, not confidently attributed. |
| A5 | Up to seven patch candidates per game are selected by deterministic rules from official-feed items with update/patch or new-content title signals and substantive body content. | This targets 25–40 episodes across the four-game pilot while covering named content updates that do not use the word “update” in the title. | Candidate status is a triage signal, not verified build linkage. Rule version and evidence are exported; all collected announcements remain present. |
| A6 | Publication time anchors review windows unless a separately verified release timestamp is provided. | Steam's public news record has a publication timestamp; it does not guarantee the build became effective at that instant. | `release_at_utc` remains null in this stage; the anchor source is explicit. |
| A7 | Review windows are closed Unix-second intervals: before `[anchor-14d, anchor-1]`, early `[anchor, anchor+7d]`, late `[anchor+7d+1, anchor+14d]`. | Integer bounds match the API's inclusive `date_range_start` and `date_range_end`, without a one-second overlap between adjacent segments. | Different patch windows can overlap; review revisions are stored once and many-to-many membership is separate. |
| A8 | Raw responses are content-addressed JSON blobs; run manifests record retrieval time, request parameters, source endpoint, status, code revision, and payload hash. Derived normalized tables are Parquet. | This separates immutable source evidence from compact analytical tables and makes reruns auditable. | Retrieval timestamps naturally differ between runs; source-derived rows and blob hashes remain deterministic for identical payloads/configuration. |
| A9 | `IStoreService/GetAppList` is optional game-catalog discovery. The documented partner host returned 403; the public API host succeeded with the configured key. | The method page lists the partner host, while host-level authentication guidance requires publisher keys there. The user-suggested public host was live-tested. | The complete query snapshot has 194,280 distinct game records across four pages, including every pilot ID. The key is never written to manifests or logs. See [`CATALOG_FOLLOWUP.md`](CATALOG_FOLLOWUP.md). |
| A10 | Linked note URLs are extracted and preserved, while arbitrary external URLs are not fetched automatically. | Steam news bodies can point to external sites; fetching arbitrary hosts creates provenance, access, and safety problems. | The report identifies external links as a full-note coverage gap. Steam Community/Store links may be fetched only through an explicit, host-allowlisted option. |
| A11 | The default request budget is bounded and sequential with a 0.5-second minimum between attempts; 429 and transient server/network failures use capped exponential backoff with jitter and `Retry-After` support. | Steam does not publish a numeric public request quota for these methods; a conservative client should honor throttling rather than assume a quota. | Every attempt consumes budget; partial windows and checkpoints are marked incomplete. |
| A12 | Raw review pages may include SteamIDs and other author metadata returned by Steam. | The user requested source-faithful raw records and Steam documents these author fields. | Raw data remains local and is git-ignored. Do not publish raw blobs; future exports should minimize author fields. |
| A13 | The review-window page cap applies per run, not cumulatively. | A fixed per-run cap makes each bounded invocation advance an incomplete window from its saved cursor. | Repeated runs continue where they left off; `--refresh` starts again from the first page. |
| A14 | Review collection defaults to `reviews.languages = ["all"]`; an empty list is rejected. | Steam's API contract says an empty list means English and `all` means every language. | Explicit filters are preserved verbatim in manifests, request observations, query signatures, and filter-specific checkpoints. Filter changes do not overwrite the all-language checkpoint or alter review IDs. |
| A15 | Steam's `language` code and original Unicode review text are ingestion evidence; detected language is a separate nullable processing field. | Steam metadata can be missing or incorrect, and reviews can contain mixed-language text and game terms. | Ingestion does no translation, transliteration, or language detection. Unknown codes remain unchanged and are flagged in coverage reports. |
